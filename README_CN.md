# 结构
## llm
实现了与大语言模型的不同交互方式，支持本地部署和远程API调用，并且包含了错误重试机制和调试支持

## llm_local_server
些文件提供了一个完整的服务端和客户端架构，服务端使用不同的大语言模型（如CodeLlama、Gemma等）生成文本或代码，客户端则通过HTTP请求与之交互。

## methods
### selection
展示了不同的父代选择策略(均匀随机选择m个个体、给每个个体分配不同的权重来选择父代、基于个体的适应度值来进行选择、锦标赛选择)，在进化算法（例如遗传算法）中常用于从现有种群中选择个体进行繁殖。

ps:锦标赛选择:从种群中随机选择一小部分个体（锦标赛大小为2），然后根据这些个体的适应度进行竞争，选择适应度最好的个体作为父代。
### management
涉及了几种优化算法中的种群管理和贪心策略(贪心算法、模拟退火算法、基于贪心策略的种群管理方法)

ps:基于贪心策略的种群管理方法:选择当前种群中的最好个体。如果新的解比当前的解更好，就替换掉种群中的最差个体。
### localsearch
结合了进化算法和大语言模型（LLM）的力量，目的是通过进化过程生成、修改和优化算法。

LS 类表示局部搜索（Local Search）算法，使用大语言模型（LLM）与其他选择策略（如选择父代）来实现进化过程。
在该算法中，通过种群管理、选择算子、进化算子等组合来生成新的个体（算法），并进行多次迭代。文件中使用了本地或远程LLM来生成新的算法代码，并进行性能评估（适应度打分）。
### eoh
通过进化过程生成或修改算法，利用LLM生成代码

Eoh基于进化优化（Evolutionary Optimization）的框架。该类用于执行一系列优化任务，利用选择、种群管理、评估等操作模拟进化过程，以寻找优化问题的最佳解。
### ael
结合进化优化算法与大语言模型（LLM）的框架，旨在通过进化算法生成、修改和优化算法，并结合加速技术提升性能

AEL 类，表示一个基于进化优化算法的框架（AEL）。该类执行优化任务，并通过进化过程生成新算法。

#### 以上三种算法的区别
1. EOH 拥有最丰富的进化算子（6种）

    i1：从零创建算法  e1：基于多父代创建完全不同形式的算法  e2：基于多父代识别共同骨干思想后创新  
    m1：对单父代进行结构修改   m2：对单父代进行参数修改  m3：泛化增强（识别过拟合组件并简化）

    特点：
    强调算法的多样性、e2算子能识别共同模式、m3专门针对过拟合问题、独立于AEL的完整实现

2. AEL (可能是Algorithm Evolution Learning)简化的进化框架
    算子数量：仅3种基本算子

    i1：从零创建算法    crossover：基于多父代创建算法    mutation：基于单父代修改算法

    特点： 代码相对简单、明确支持本地LLM调用、算子名为crossover/mutation而非e1/m1

3. LS (Local Search / Simulated Annealing)模拟退火式局部搜索

    算子：与EOH相似的算子集（但用法不同）

    关键特征：主要围绕当前最优解进行探索、  温度控制、  Metropolis准则：概率性接受劣解、  种群管理不同：self.manage.population_management(population, offsprings[0], temperature)
